# beat to light

Godot 4 で作った、4レーンの落下型リズムゲームです。完成品ではなく「遊べる土台」です。
タイミング、スコア、譜面の形式、画面遷移はすべて動いていて、どの部品も小さく、
差し替えやすくしてあります。

Godot **4.7.2** で `project.godot` を開き（プロジェクトマネージャーの「インポート」から）、
F5 で起動します。CI もこの版でテストしています。Godot は
<https://github.com/godotengine/godot/releases/tag/4.7.2-stable> から入手できます。
標準版で十分で、.NET 版（ファイル名に `mono` が付くもの）は不要です。

Godot を入れずに遊ぶなら、Windows 用の .exe もあります（「Windows 用の実行ファイル」の節）。
譜面は、ゲームとは別のアプリ「譜面エディタ」で作れます（「譜面エディタ」の節）。

## 操作

| キー | 動作 |
| --- | --- |
| `D` `F` `J` `K` | レーン1〜4 |
| `R` | 最初からやり直す |
| `F1` | オートプレイの切り替え |
| `Esc` | 曲選択に戻る（曲選択画面では終了。譜面エディタから試遊しているときはエディタに戻る） |

帯の付いたノーツはロングノーツです。頭が判定ラインに来たら押し、帯の終わりまで
押し続けます（詳しくは「判定」の節）。

レーンのキーは物理的なキーの位置で判定するので、キー配列が QWERTY でなくても
同じ指の位置で遊べます。変更は `scripts/key_binds.gd` で行います。

## 譜面エディタ

譜面はゲームとは別のアプリで作ります。Windows では `beat_to_light_chart_editor.exe` を
起動します（入手方法は「Windows 用の実行ファイル」の節）。Godot から使うときは
`scenes/editor.tscn` を開いて **F6** です。

真ん中が譜面です。プレイ画面と同じく下から上へ時間が進み、下のほうの白い線がカーソルです。
左から小節番号、曲の**波形**、レーンの順に並び、横線は小節線、拍、スナップの細かさの順に
薄くなります。拍の線は波形の上にも引いてあるので、音の立ち上がりと線を見比べて置けます。
右側で曲名・BPM などを設定し、上のツールバーでファイル・再生・試遊を操作します。

**マウスで直接置いて動かせます。**

| 操作 | 動作 |
| --- | --- |
| 空いている所をクリック | 通常のノーツを置く |
| 空いている所を上か下へドラッグ | ロングノーツを置く |
| ノーツをドラッグ | 動かす（時間方向にもレーンをまたいでも。選んでいるノーツはまとめて動く） |
| ロングノーツの端をドラッグ | 長さを変える |
| 右クリック / 右ボタンでなぞる | 消す（なぞった所はまとめて消える） |
| `Shift` + ドラッグ | 囲んだノーツを選ぶ（`Ctrl` も押すと追加で選ぶ） |
| `Ctrl` + クリック | 選ぶノーツを1つずつ足す・外す |
| 波形・小節番号の所をクリック | カーソルをそこへ移す（ドラッグするとスクロール） |

置く位置は **Snap**（1/1〜1/8、3連符は 1/3 と 1/6。数字キー `1`〜`6` でも切り替え）に
揃います。マウスを乗せると置く位置に薄くノーツが出て、ドラッグ中は動かした先が表示されます。
重なって置けない場所なら赤くなり、離しても何も変わりません。マウスカーソルの形も、
ノーツの上では移動、端の上では長さ変更に変わります。

**キーで録ることもできます。** **Record** をオンにして再生し、曲に合わせて `D` `F` `J` `K` を
叩くと、押した位置がスナップに揃えられてノーツになります。半拍以上押し続けると
ロングノーツです。曲がないときは止めるまで再生が続きます。1回の録音は `Ctrl+Z` 1回で
まとめて取り消せます。

| キー | 動作 |
| --- | --- |
| `Space` | 再生・停止（カーソルの位置から） |
| `Delete` / `Backspace` | 選んだノーツを消す |
| `Ctrl+C` / `Ctrl+X` / `Ctrl+V` | コピー / 切り取り / カーソルの位置に貼り付け（貼り付けたノーツは選ばれた状態になる） |
| 矢印キー | 選んだノーツを動かす（上下はスナップ1つ分、`Shift` で4つ分。左右はレーン） |
| `M` | 選んだノーツを左右反転 |
| `Ctrl+A` / `Esc` | すべて選ぶ / 選ぶのをやめる |
| `Ctrl+Z` / `Ctrl+Y` | 元に戻す / やり直し |
| マウスホイール | スクロール（`Shift` で1拍ずつ。何も選んでいなければ上下キーでも） |
| `Ctrl` + ホイール | 拡大・縮小（マウスの位置を中心に） |
| `Home` / `End` | 先頭 / 最後のノーツへ |
| `Ctrl+N` / `Ctrl+O` / `Ctrl+S` / `Ctrl+Shift+S` | 新規 / 開く / 保存 / 名前を付けて保存 |

**曲を流す：** **Music...** で .ogg を選ぶか、.ogg をウィンドウにドラッグ＆ドロップすると、
再生中に流れ、波形が表示されます。曲の終わりは橙色の線（`music ends`）です。曲の頭と拍が
ずれているときは **Offset**（秒）で、拍の線が波形の山に重なるように合わせます。速い所は
**Speed** を 75% や 50% に落とすと置きやすくなります（音の高さも下がります）。
**Metronome** は拍ごとのクリック、**Note sounds** はノーツの位置で鳴る音です。

**試遊：** **Test play** は最初から、**Test from cursor** はカーソルの位置からゲームで
遊びます（カーソルより前のノーツは除かれます）。リザルト画面の **Back to editor** か、
プレイ中の `Esc` でエディタに戻ります。カーソル位置や取り消しの履歴もそのまま残っています。
保存しなくても試遊できます。

**開く・保存：**

- **Open...** を押すと、同梱の譜面と自分の譜面が一覧に出ます。**Browse...** で他の場所の
  ファイルも開けます。.json をウィンドウにドラッグ＆ドロップしても開けます。
- 新しい譜面を初めて保存するときは、保存先を聞かれます。最初に開く場所はユーザーフォルダの
  `songs/`（Windows では `%APPDATA%\Godot\app_userdata\beat to light\songs`）です。ここに
  保存した譜面は、ゲームの曲選択に `[mine]` と付いて、同梱の譜面の後に並びます。
- 曲は保存するときに譜面と同じフォルダへコピーされるので、譜面と曲はいつも一緒に置かれます。
  同じ名前の別の曲があるときは、上書きせずに `song_2.ogg` のような名前でコピーします。
- .exe では同梱の譜面は書き換えられないので、保存すると保存先を聞かれます（別の名前で残ります）。
  Godot から起動したときは `songs/`（プロジェクトの中）にそのまま保存できるので、
  コミットすれば同梱の譜面になります。
- 保存していない変更があるときに、新規・開く・ウィンドウを閉じるを選ぶと、
  **Save** / **Don't save** / **Cancel** を聞かれます（試遊中に閉じたときも、エディタに戻って
  聞きます）。

## タイミングの仕組み

時刻はすべて `Conductor.chart_time` から計算します。各部品が自分で経過時間（delta）を
積み上げることはしないので、フレーム落ちがあってもノーツが音楽からずれていきません。

- 曲が読み込まれているときは、コンダクターが音声の再生位置を読み取り、
  `AudioServer.get_time_since_last_mix()` と出力遅延で補正します。これで画面と
  聞こえる音が一致します。
- 曲がないときはシステムの時計で進み、代わりに `Sfx.play_tick()` がメトロノームを
  鳴らします。同梱の譜面は2つともこの方式なので、音源を用意する前から遊べます。

ノーツの画面上の位置は「あと何秒で叩くか」だけで決まります：
`Playfield.y_for(note.time - chart_time)`。`scroll_time` 秒先のノーツは画面の一番上に、
0秒のノーツは判定ラインの上にあります。

## 判定

| 判定 | タイミングのずれ | 配点 |
| --- | --- | --- |
| CRITICAL | ±25ms 以内 | 100% |
| PERFECT | ±40ms 以内 | 95% |
| GREAT | ±80ms 以内 | 50% |
| GOOD | ±150ms 以内 | 20% |
| MISS | それより外、または押さなかった | 0% |

早押しと遅押しは同じ扱いです。スコアは、すべての判定が CRITICAL のとき 1,000,000 点に
なるよう正規化しています（すべて PERFECT なら 950,000 点）。

CRITICAL のうち ±16ms 以内は**内部精度**として別に数えます。画面には出さず、表示も
配点も CRITICAL と同じです。件数はリザルトのデータ（`GameState.last_result` の
`inner_critical`）にだけ残ります。幅は `judge.gd` の `INNER_CRITICAL_WINDOW` です。

### ロングノーツ

ロングノーツの判定は1本につき1回で、終点の判定はありません。

- 頭を押したタイミングで、通常のノーツと同じように判定が決まります（押した瞬間に表示）。
- 終点まで押し続けると、その判定がそのまま確定します。コンボとスコアに入るのはこの時点です。
  終点を過ぎてから離すのはいつでもかまいません。
- 途中で離すと、そのロングノーツは MISS になります。ただし終点の 150ms 前より後に
  離した場合は、最後まで押し続けた扱いです（`judge.gd` の `HOLD_RELEASE_GRACE`）。
- 頭を逃した場合も MISS です。

## 譜面の書き方

`songs/` に JSON ファイルを置くと曲選択に表示されます。曲選択はファイル名順に並ぶので、
ファイル名の先頭に番号を付けて順番を決めています。ふつうは譜面エディタで作れば十分で、
この形式を知る必要はありません。エディタが保存するファイルも同じ形式です。

```json
{
  "title": "First Light",
  "artist": "tutorial chart",
  "bpm": 120,
  "offset": 0.0,
  "lane_count": 4,
  "scroll_time": 1.1,
  "music": "",
  "notes": [
    {"beat": 4, "lane": 0},
    {"beat": 4.5, "lane": 2},
    {"beat": 6, "lane": 1, "length": 2}
  ]
}
```

- `beat` は譜面の先頭から数えた拍です。4/4拍子なら `0.5` が8分音符1つ分です。
  手で細かく置きたい場合は、代わりに `"time"`（秒）でも指定できます。
- `lane` は左から 0, 1, 2, … と数えます。
- 同じ拍に別レーンのノーツを2つ置くと同時押しになります。特別な書き方は要りません。
- `length` を付けると、その拍数だけ続くロングノーツになります（秒で指定したいときは
  `"duration"`）。付けないか 0 なら通常のノーツです。
- ロングノーツの最中に、同じレーンへ次のノーツを置くことはできません。押しっぱなしの
  キーでは叩けないためです。同梱の譜面は、テストでこれを検査しています。
- `scroll_time` はノーツが現れてから叩くまでの秒数です。小さいほど速く、難しくなります。
- `offset` は全ノーツを指定した秒数だけ後ろにずらします。譜面を音源に合わせるときに使います。

## 曲を付ける

譜面エディタの **Music...** を使うのがいちばん簡単です。手で書く場合は、譜面の隣に
`.ogg` を置き、譜面の `"music"` にそのファイル名（`"mysong.ogg"`）を書きます。
`"res://songs/mysong.ogg"` のようなパスでもかまいません。曲があると、コンダクターは
自動的に音声の再生位置を基準にするようになります。曲に対してノーツがいつも早い・遅いと
感じたら、ノーツを動かすのではなく `offset` を調整してください。

## 手触りの調整

`scripts/judge.gd` に1か所にまとめてあります：判定幅（どこまでずれても判定されるか）、
各判定の配点、ランクの境界、最大スコア。スコアは正規化しているので、ノーツ数に
関係なく、すべての判定が CRITICAL なら常に `MAX_SCORE` になります。

## Windows 用の実行ファイル（.exe）

Godot を入れなくても使える .exe を、CI が作ります。ゲーム（`beat_to_light.exe`）と
譜面エディタ（`beat_to_light_chart_editor.exe`）の2つです。どちらもデータが中に入っているので、
.exe 1つで動きます。Mac 用はまだありません。

- **入手方法：** `main` に変更が入るたびに作られます。GitHub の **Actions** タブで「Tests」の
  実行を開き、下のほうの **Artifacts** にある `beat-to-light-windows` をダウンロードして
  展開すると、2つの .exe が入っています。
- 譜面エディタで保存した譜面は、ゲームの曲選択にそのまま並びます（2つのアプリは同じ
  ユーザーフォルダを使います）。
- **保存期間は7日です。** 期限が切れたときや、`main` 以外のブランチの .exe が欲しいときは、
  Actions タブで「Tests」→ **Run workflow** からブランチを選んで実行すると作られます。
- プルリクエストでは作りません。非公開リポジトリの無料枠では成果物を置ける容量が 500MB で、
  .exe は1つ約36MB（1回で2つ）あるためです。

**初めて起動するとき：** 署名のない .exe なので、Windows が「Windows によって PC が
保護されました」と表示することがあります。「詳細情報」→「実行」で起動できます。

**手元で作るとき：** Godot で **Project → Export…**（英語 UI での名称）を開き、
ゲームは「Windows Desktop」、譜面エディタは「Chart Editor (Windows)」を選んで書き出します。初回は **Manage Export Templates** から
エクスポートテンプレート（約1.3GB）を入れる必要があります。書き出し先の既定は `build/` で、
Git の管理対象からは外してあります。

書き出し設定は `export_presets.cfg` にあります。`tests/` は含めず、.exe には `icon.svg` の
アイコンと名前が入ります。2つは同じプロジェクトから書き出していて、違いは最初の画面だけです。
譜面エディタの設定には `chart_editor` という機能タグが付いていて、`project.godot` の
`run/main_scene.chart_editor` がそのときだけ最初の画面を `scenes/editor.tscn` に替えます。

## テスト

テストに必要なのは Godot 本体だけで、プラグインやアドオンは要りません。画面を出さずに
（ヘッドレスで）動くので、手元の PC だけでなくサーバーや CI でも実行できます。

### 必要なもの

- **Godot 4.7.2**（入手先は冒頭のとおり）。4.4、4.5 でも全テストが通ることを
  確認しています。4.3 以前は対象外です（譜面エディタの波形に、4.4 で追加された
  `AudioStreamPlayback.mix_audio()` を使っているため、4.3 ではスクリプトを読み込めません）。
- **bash**（`run_tests.sh` 用）。macOS、Linux、Windows の Git Bash や WSL で使えます。
  bash のない Windows では、下に書いたコマンドを直接実行してください。

ヘッドレス環境には音声デバイスがありません。その場合 Godot はダミーの音声ドライバーに
切り替わってそのまま動きます。テストも、音が聞こえることには依存していません。

### テストの実行

プロジェクトのフォルダで：

```sh
tests/run_tests.sh                                   # PATH 上の godot を使う
GODOT=~/bin/Godot_v4.7.2-stable_linux.x86_64 tests/run_tests.sh
```

bash がない場合（PowerShell やコマンドプロンプト）は、プロジェクトのフォルダで
次の2つを順に実行します：

```sh
godot --headless --editor --quit --path .            # 初回のみ
godot --headless --path . res://tests/test_runner.tscn
```

エディタから実行する場合は、`tests/test_runner.tscn` を開いて **F6**（Run Current Scene）を
押します。結果は出力パネルに表示されます。

すべて成功すると次のように表示され、終了コード 0 で終わります。1件でも失敗すると
終了コード 1 で終わり、期待した値と実際の値が並べて表示されます。最後の集計行が出ないまま
Godot が終わったとき（テスト中のコードがゲームを終了させてしまった場合など）は、
成功に見えないよう終了コード 3 で終わります：

```
  PASS  test_judge.test_exact_hit_is_critical
  ...
  PASS  test_autoplay_run
  ...
  PASS  test_editor_run

68 passed, 0 failed (19.1s)
```

> **新しくチェックアウトした直後の初回実行について。** Godot はプロジェクトを
> インポートしたときに初めて、グローバルなクラス名（`Chart`、`Judge`、`Conductor` など）を
> 認識します。そして `.godot/` はリポジトリに含めていません。インポートしないままだと、
> すべてのスクリプトが `Identifier "Chart" not declared` で失敗します。`run_tests.sh` は
> `.godot/` がなければ自動でインポートします。新しく `class_name` を追加してこのエラーが
> 出たときは、上のインポートのコマンドをもう一度実行してください。

> **制限時間について。** スクリプトに文法エラーがあっても Godot は終了せず、空の画面の
> まま待ち続けます。そのため `run_tests.sh` は90秒で実行を打ち切り、終了コード 124 で
> 終わってその旨を表示します。出力から `SCRIPT ERROR` を探すと、壊れているファイルが
> わかります。テストが増えて本当に時間がかかるようになったら、`TEST_TIMEOUT=300` のように
> 上限を延ばしてください（macOS では `brew install coreutils` で入る `gtimeout` が必要です。
> ない場合は時間制限なしで実行されます）。

### CI（GitHub Actions）

リポジトリ直下（このフォルダの外）にある `.github/workflows/tests.yml` が、同じ
`run_tests.sh` を GitHub のサーバー上で実行します。

- **実行されるタイミング：** `main` へのプッシュ時、プルリクエストの作成・更新時、
  Actions タブの **Run workflow** から手動で実行したとき。
- **結果の確認場所：** プルリクエスト画面の下部のチェック欄、各コミットの横の ✓/✗、
  詳しいログは **Actions** タブ。
- **Godot はキャッシュされます。** 初回は Godot（4.7.2 で約75MB）をダウンロードして保存し、
  2回目以降は数秒で復元してダウンロードを省きます。どちらになったかはログでわかります。
  キャッシュが使われたときは「Download Godot (cache miss only)」の手順がスキップされます。
- プルリクエストでは、そのプルリクエスト自身の過去の実行と、`main` で保存された
  キャッシュを使えます。`main` で一度も実行されていないうちは、新しいプルリクエストは
  初回の実行で Godot をダウンロードします。また、7日間使われなかったキャッシュは GitHub が
  削除するので、その次の実行で再びダウンロードして保存し直します。
- **Godot のバージョンを変えるには：** ワークフロー先頭の `GODOT_VERSION` を書き換えます
  （`4.7.2-stable` のようなリリースのタグ名）。キャッシュはこの値ごとに保存されるので、
  新しいバージョンは一度だけダウンロードされ、以降はキャッシュから使われます。
- テストが通ると、Windows 用の .exe も作ります（「Windows 用の実行ファイル」の節）。
- 同じブランチに新しくプッシュすると、古くなった実行は自動で取り消されます。さらに念のため
  1回の実行は最大10分で打ち切られるので、止まった実行が Actions の利用時間を使い切る
  ことはありません。

合成したキー入力は1フレームほど遅れて届くことがあるので、入力のテストは頭の判定に
CRITICAL までは求めず、GREAT 以上なら合格にしています。こうすることで遅いマシンでも
誤って失敗せず、それでいて入力処理が壊れていれば検出できます。

プレイテストでは、ゲーム画面に切り替えるのではなく、ゲームのシーンをテストランナーの
中に入れて動かします。`game.gd` は終了時に `run_finished(result)` を発行し、自分が
プレイ中のシーンであるときだけ画面遷移するので、これが可能になっています。どのノーツが
どう判定されたかは、ノーツの判定が確定するたびに発行される `note_judged` シグナルで
記録しています。

### テストを追加する

単体テストの場合：`tests/test_something.gd` を作って `TestCase` を継承し、名前が `test_` で
始まるメソッドを書いて、`test_runner.gd` の `UNIT_TESTS` にそのスクリプトを追加します。
メソッドごとに新しいインスタンスが作られます。

```gdscript
extends TestCase

func test_quarter_note_at_60_bpm() -> void:
	var chart := Chart.from_dict({"bpm": 60, "notes": [{"beat": 1, "lane": 0}]})
	check_near(chart.notes[0].time, 1.0, "60 BPM では1拍が1秒")
```

使えるチェックは `check(condition, message)`、`check_eq(actual, expected, message)`、
`check_near(actual, expected, message, tolerance)` の3つです。GDScript には例外がないので、
チェックに失敗してもメッセージを記録して、テストはそのまま続きます。

ゲームを実際に動かすテストの場合：代わりに `PlayTest` を継承し、`run(host)` を上書きして、
`PLAY_TESTS` に追加します。`test_input_run.gd` が見本になります。エディタを動かすテストは
`test_editor_run.gd` が見本です。

> **マウス入力を送るときの注意。** ヘッドレスのウィンドウは 64×64 ピクセルしかなく、
> マウスの座標はウィンドウの座標として届きます。画面上の位置をそのまま送ると、ずれた
> 場所をクリックすることになります。`test_editor_run.gd` の `_place()` のように
> `get_viewport().get_final_transform()` で変換してから送ってください。

### テストでは確かめられないこと

ヘッドレスでは何も描画されず、音も鳴りません。レーン、HUD、タイミングまわりのコードを
変えたら、次の点は手で確認してください：

- [ ] 出荷するウィンドウサイズで、レーン・ノーツ・判定ラインの見た目が正しい。
- [ ] HUD の文字が収まっていて、レーンに重なっていない。
- [ ] 実際の曲で、聞こえる拍の位置にノーツが来る。いつも早い・遅い場合は譜面の `offset` を調整する。
- [ ] ヒット音とミス音が鳴り、曲がないときはメトロノームが鳴る。
- [ ] 譜面エディタの **Open...** の **Browse...**、**Save as...**、**Music...** でファイルを選ぶ画面が開く（OS 標準の画面を使うので、テストでは開いていません）。
- [ ] 譜面エディタで再生したとき、曲とノーツの音が合っていて、波形の山と拍の線が揃う。
- [ ] 譜面エディタのウィンドウにファイルをドラッグ＆ドロップすると開ける（テストでは受け取った後の処理だけを確かめています）。

## 次に手を付けるなら

- **譜面エディタの拡張。** 途中での BPM 変更、レーン数の変更、タップで BPM を測る機能などは
  まだありません。編集は `scripts/editor/chart_doc.gd` に、画面の操作は
  `editor_timeline.gd` にまとめてあります。

- **判定エフェクト。** `game.gd` の `note_judged(lane, rank)` シグナルがちょうど良い
  差し込み口です。ノーツの判定が確定するたびに、レーンと判定の種類を付けて発行されます
  （ロングノーツでは終点に着いたときか、途中で離したとき）。キーを押した瞬間の反応なら
  `Playfield.flash()` です。
- **ロングノーツの拡張。** 今は一度離すとそこで終わりです。途中で離しても押し直せば
  続けられるようにする、押している間もコンボが増える（ティック）、といった変化は
  `game.gd` の `_release_lane` と `_judge_by_time` が出発点になります。
- **本格的な画像。** `note.gd` と `playfield.gd` はすべてコードで描いています。
  `_draw()` をスプライトに置き換えてください。
- **タイミング調整画面。** コンダクターの `offset` は全体共通の値です。プレイヤー自身の
  入力遅延を測る調整画面を作れば、この値を自動で設定できます。
